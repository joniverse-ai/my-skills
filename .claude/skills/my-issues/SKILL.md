# 내 파트 이슈 체크

현재 프로젝트의 GitHub 이슈를 확인하고, 사용자의 역할에 해당하는 항목을 분류·요약한다.

## 사전 정보

- 사용자 역할: **B② (분석·생성)**
- 담당 파일: `lib/openai/extract.ts`
- 담당 기능: `extractStyle`, `generateCharacterSheet`, `spec/vocabulary.json`
- 관련 키워드: extract, style, character sheet, vocabulary, VLM, 레퍼런스, gpt-image, B②

## 실행 순서

1. `gh issue list --state open --limit 30` 으로 열린 이슈 목록을 가져온다.
2. 각 이슈의 본문을 `gh issue view <번호>` 로 읽는다.
3. 아래 기준으로 3단계 분류한다:

### 분류 기준

| 분류 | 조건 |
|---|---|
| **직접 조치** | B② 담당 파일·기능이 변경 대상이거나, B②가 assignee이거나, B②의 코드가 원인인 이슈 |
| **관련됨** | B②의 코드 출력이 선행 조건이거나, B② 인터페이스에 영향을 주는 이슈 (다른 담당자) |
| **무관** | B②와 접점이 없는 이슈 |

4. 결과를 아래 형식으로 보여준다:

```
## 직접 조치 필요
- #번호 제목 — (한 줄 요약: 뭘 해야 하는지)

## 관련됨 (지켜보기)
- #번호 제목 — (한 줄 요약: 어떻게 관련되는지)

## 무관
- #번호, #번호, ...
```

5. 마지막에 **우선순위 추천**을 한 문장으로 덧붙인다 (가장 급한 것 + 이유).
