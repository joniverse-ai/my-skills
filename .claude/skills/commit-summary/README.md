# commit-summary

## 이 스킬이 필요한 이유

팀에서 커밋 메시지 양식이 제각각이면 나중에 히스토리를 훑을 때 어떤 커밋이 무슨 작업인지 파악하기 어렵다.
특히 코드 리뷰, 릴리스 노트 작성, 장애 원인 추적 등에서 일관된 커밋 메시지는 큰 차이를 만든다.

이 스킬은 `git diff`를 기반으로 변경 사항을 자동 분석하고, 팀이 정한 `[범위] 한 일 (#이슈)` 양식에 맞춰 요약해 준다.
사람이 직접 diff를 읽고 분류할 필요 없이, 일관된 품질의 커밋 메시지를 빠르게 만들 수 있다.

## 사용 예시

```
/commit-summary
```

실행하면 현재 변경 사항을 분석해 아래와 같은 형식으로 요약한다:

```
[auth] 로그인 세션 만료 시간 수정 (#42)
[ui] 다크모드 토글 버튼 추가 (#38)
```
